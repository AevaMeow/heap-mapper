# heap-mapper

`heap-mapper` — прототип генератора тестовых данных для проверки путей
выполнения функций на языке C, которые работают с динамическими структурами
данных.

На вход подаётся описание пути в формате JSON. Прототип строит модель памяти,
подбирает значения указателей и полей, а затем генерирует C harness. Этот файл
создаёт входную структуру и вызывает указанную целевую функцию.

Прототип реализован на Java 21. Генерируемые тесты представлены на языке C.

## Назначение

Прототип строит конкретные входные данные, необходимые для выполнения
выбранного пути программы. Поддерживаются:

- односвязные, двусвязные и циклические списки;
- деревья и другие самоссылочные структуры;
- нулевые указатели и алиасы;
- ограничения равенства и неравенства указателей;
- ограничения на целочисленные поля;
- нарушения `null dereference`, `use-after-free` и `double free`.

После обработки пути прототип возвращает один из статусов:

| Статус | Значение |
| --- | --- |
| `SAFE` | входные данные построены, нарушение не обнаружено |
| `UNSAT` | ограничения пути являются противоречивыми |
| `VIOLATION` | построен вход, приводящий к ошибочной операции |
| `UNSUPPORTED` | путь пока не поддерживается прототипом |
| `TIMEOUT` | превышено время выполнения |
| `COMPILE_ERROR` | сгенерированный C-код не удалось скомпилировать |

## Требования

- JDK 21;
- Apache Maven;
- GCC или Clang.

Сборка проекта:

```bash
mvn clean package
```

Исполняемый JAR создаётся по адресу:

```text
target/heap-mapper-1.0.0-all.jar
```

## Применение

Пример полного цикла генерации и выполнения теста для бинарного дерева:

```bash
java -jar target/heap-mapper-1.0.0-all.jar \
  examples/binary_tree.json \
  --out generated/tree.c \
  --target-source examples/targets/inspect_tree.c \
  --run
```

В результате создаётся файл `generated/tree.c` с кодом подготовки входных
данных. Он компилируется вместе с целевой функцией из
`examples/targets/inspect_tree.c`. Полученная программа сохраняется в
`generated/tree` и запускается автоматически.

По умолчанию используется GCC. Компилятор и путь к исполняемому файлу могут
быть переопределены:

```text
--compiler clang --executable generated/tree-test
```

Параметр `--target-source` задаёт файл с целевой функцией. Параметр `--run`
запускает собранный тест и проверяет сообщения санитайзеров. Если эти
параметры не указаны, создаётся только C harness.

## Схема работы

Работа с прототипом состоит из следующих этапов:

1. Статический анализатор обнаруживает потенциально ошибочный путь.
2. Условия и операции выбранного пути записываются в JSON.
3. `heap-mapper` строит модель памяти и подбирает входные данные.
4. На основе модели генерируется C harness.
5. Harness компилируется совместно с анализируемой целевой функцией.
6. Результат запуска проверяется с помощью AddressSanitizer и
   UndefinedBehaviorSanitizer.

Сейчас трасса статического анализатора переносится в JSON вручную.

## Формат входных данных

JSON содержит описание структуры, имя входного указателя, имя целевой функции
и последовательность операций пути:

```json
{
  "structure": {
    "name": "Node",
    "fields": [
      {"name": "key", "type": "int"},
      {"name": "next", "type": "pointer", "target": "Node"}
    ]
  },
  "entry_pointer": "head",
  "target_function": "inspect_list",
  "path": [
    {"op": "constraint", "expr": "head != NULL"},
    {"op": "constraint", "expr": "head.key == 1"},
    {"op": "assign", "lhs": "second", "rhs": "head.next"},
    {"op": "constraint", "expr": "second.key == 2"}
  ]
}
```

Поддерживаются операции `constraint`, `assign`, `malloc`, `free` и `deref`, а
также поля типов `int` и `pointer`. Примеры JSON и целевых функций находятся
в каталоге `examples`.

## Подтверждение нарушения

Пример генерации и выполнения теста для разыменования нулевого указателя:

```bash
java -jar target/heap-mapper-1.0.0-all.jar \
  examples/null_dereference.json \
  --out generated/null_dereference.c \
  --target-source examples/targets/trigger_null_dereference.c \
  --run
```

Для результата `VIOLATION` проверка считается успешной, если санитайзер
обнаружил ожидаемый тип нарушения. Поэтому аварийное завершение программы в
этом случае подтверждает воспроизведение ошибки.

## Модульное тестирование

Модульные и интеграционные тесты написаны на Groovy и Spock:

```bash
mvn clean test
```

## Экспериментальная оценка работы прототипа

Тестовые наборы расположены в каталоге `benchmarks`. Запуск полной выборки:

```bash
java -cp target/heap-mapper-1.0.0-all.jar \
  heapmapper.experiment.BenchmarkRunner \
  benchmarks/all-v1/manifest.json \
  --out reports/all-v1
```

Результаты сохраняются в каталоге `reports/all-v1`.

## Ограничения

- прототип не анализирует исходный код C/C++ автоматически;
- трасса статического анализатора переносится в JSON вручную;
- не поддерживаются арифметика указателей, приведения типов и `union`;
- отсутствует межпроцедурный анализ;
- один входной документ описывает одну самоссылочную структуру;
- целевая функция должна находиться в отдельном C-файле, а её сигнатура должна
  соответствовать описанию в JSON.

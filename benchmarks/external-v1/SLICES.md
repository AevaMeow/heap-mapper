# Manual path slices

Внешние C-программы не передаются `heap-mapper` напрямую. Для десяти случаев
вручную выделен path-sensitive обратный срез и нормализован в JSON.

| ID | Исходный файл | Критерий среза | Сохранённые зависимости |
| --- | --- | --- | --- |
| E01 | `sll2n_append_equal.c` | проверка списка после `sll_append` | три узла, `data == 1`, `tail->next == NULL` |
| E02 | `sll2n_append_unequal.c` | проверка добавленного значения | цепочка `1, 1, 5`, конец списка |
| E03 | `sll2n_insert_equal.c` | проверка после вставки в индекс 1 | три узла со значением `1` |
| E04 | `sll2n_insert_unequal.c` | проверка среднего элемента | цепочка `1, 5, 1`, конец списка |
| E07 | `sll2c_append_equal.c` | проверка цикла после append | три узла и обратная ссылка на `head` |
| E10 | `sll2c_update_all.c` | проверка обновлённых элементов | цикл из значений `2, 3` |
| E11 | `dll2n_append_equal.c` | прямая проверка результата append | `next`, `prev`, три значения `1` |
| E14 | `dll2c_append_equal.c` | обход циклического DLL | цикл из трёх узлов и все обратные ссылки |
| E17 | `tree-1.c` | `node->parent = NULL` после нуля итераций create-loop | `node == NULL`, запись через `node` |
| E19 | `tree-3.c` | безопасный путь функции `inspect` | корень, левый ребёнок `value == 42`, `parent == NULL` |

Срезы для E01–E16 описывают состояние, проверяемое исходной программой после
операции со списком. Они не моделируют сами циклы создания и проверки.

E17 сохраняет конкретный дефект исходной программы: при нуле итераций
недетерминированного цикла `node` остаётся `NULL`, после чего выполняется
`node->parent = NULL`.

Остальные 30 программ не удалены. Они остаются в manifest как
`UNSUPPORTED`, а конкретная причина записана в `unsupported_reason`.
